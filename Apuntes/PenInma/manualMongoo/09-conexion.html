Tema 9

🌍 Conectando nuestra API con MongoDB

En esta lección aprenderás a conectar tu servidor Express con una base de datos MongoDB Atlas usando Mongoose. Este será tu primer paso real para trabajar con datos persistentes en la nube.

🎯 Objetivo: configurar un entorno seguro (.env) y crear una función de conexión (db.js) que permita a nuestra API comunicarse con MongoDB.

🔍 1️⃣ ¿Qué significa “conectar a una base de datos”?

Hasta ahora, nuestro servidor Express solo respondía con mensajes fijos (“ok”). Cuando conectamos a una base de datos, le damos la capacidad de:

  • Guardar datos de forma permanente (no se borran al apagar el servidor).
  • Consultar información real almacenada en colecciones.
  • Actualizar o eliminar registros concretos.

En nuestro caso, usaremos MongoDB Atlas, que es un servicio gratuito en la nube donde puedes crear bases de datos NoSQL. Para acceder, necesitamos una URI de conexión (una dirección segura que incluye usuario, contraseña y cluster).

🔐 Paso 1. Crear y configurar el archivo .env

El archivo .env sirve para guardar variables de entorno: valores que necesita nuestra aplicación pero que no deben mostrarse en el código público. En él guardaremos datos como la cadena de conexión a MongoDB Atlas y el puerto del servidor.

💡 ¿Qué es una variable de entorno?

Una variable de entorno es como una “caja de configuración externa”. El sistema la carga al iniciar la aplicación, y permite guardar información sensible o configurable, como:

  • 🔑 La URI de conexión a la base de datos MongoDB (con usuario y contraseña).
  • ⚙️ El puerto donde se ejecuta el servidor Express.
  • 🔐 Claves, tokens o URLs de servicios externos.

🔐 Ejemplo: Si subes tu proyecto a GitHub con las credenciales dentro del código, cualquiera podría verlas. Por eso guardamos esos datos en .env y añadimos el archivo al .gitignore.

📄 Cómo crear el archivo .env

  1. En la raíz de tu carpeta backend (junto a package.json y la carpeta src/), crea un archivo llamado .env.
  2. Pega dentro el siguiente contenido (ajusta tu usuario y contraseña reales):
# Cadena completa de conexión a MongoDB Atlas
MONGODB_URI="mongodb+srv://inmacontreras2709_db_user:us77dJov5goG5oaP@ici27.lfxkraj.mongodb.net/tienda?retryWrites=true&w=majority&appName=ici27"

# Nombre de la base de datos dentro del cluster
MONGODB_DB="tienda"

# Puerto del servidor local
PORT=3000

✅ Explicación de cada línea:

  • MONGODB_URI: la cadena de conexión completa que obtienes desde MongoDB Atlas (incluye usuario, contraseña, cluster y base).
  • MONGODB_DB: el nombre de la base de datos que usarás en el cluster, en este caso tienda.
  • PORT: el puerto local donde se ejecutará tu servidor Express.
⚠️ Importante: Nunca subas este archivo a GitHub. Añade una línea .env en tu archivo .gitignore para mantenerlo oculto: 
.env

🔗 Conexión con la librería dotenv

La dependencia dotenv se encarga de leer automáticamente este archivo .env cuando se inicia tu aplicación Node.js.

Al principio de tu server.js añade: 

import dotenv from "dotenv";
dotenv.config();

Desde ese momento podrás acceder a las variables con: 

process.env.MONGODB_URI
process.env.MONGODB_DB
process.env.PORT

✅ Ventaja: puedes usar el mismo código en distintos entornos (local, pruebas, producción) cambiando solo el contenido del archivo .env.

🌐 Cómo obtener tu MONGODB_URI desde MongoDB Atlas

La URI de conexión es la dirección completa que permite a tu aplicación Node.js conectarse a tu base de datos en la nube (MongoDB Atlas). Contiene tu usuario, contraseña, cluster y base de datos.

🧭 Pasos para obtenerla

  1. Accede a tu cuenta en MongoDB Atlas.
  2. Entra en tu proyecto y haz clic en tu Cluster (por ejemplo Cluster0 o ici27).
  3. Pulsa el botón Connect (arriba a la derecha).
  4. Selecciona la opción “Drivers” (no “Shell” ni “Compass”).
    ✅ Correcto: “Drivers” es la opción para conectar Node.js mediante Mongoose.
    ❌ No elijas: “Mongo Shell” ni “Compass”.
  5. Elige Driver: Node.js y Version: 5.5 o posterior.
  6. Copia la cadena que aparece en “Connection String”. Verás algo parecido a: 
    mongodb+srv://<username>:<password>@ici27.lfxkraj.mongodb.net/?retryWrites=true&w=majority
  7. Sustituye los marcadores <username> y <password> por tus credenciales reales.
  8. Añade al final el nombre de tu base de datos (por ejemplo /tienda): 
    mongodb+srv://inmacontreras2709_db_user:us77dJov5goG5oaP@ici27.lfxkraj.mongodb.net/tienda?retryWrites=true&w=majority&appName=ici27
💡 Recuerda: Esta cadena es única para tu cuenta y contiene tus credenciales. No la compartas ni la publiques tal cual.

🧠 Diferencia entre “Mongo Shell” y “Drivers”

TipoUsoEjemplo
Mongo Shell Permite conectarte manualmente desde la terminal (mongosh). mongosh "mongodb+srv://ici27..." --username tuUsuario
Driver (Node.js) Conecta tu aplicación mediante código (Mongoose o driver oficial). mongoose.connect("mongodb+srv://...")
⚠️ Importante: Si necesitas mostrar tu URI en clase o en una captura, oculta la contraseña con asteriscos: 
mongodb+srv://usuario:********@cluster0.mongodb.net/tienda
En resumen:
  • 📍 Usa la opción Drivers → Node.js en Atlas para obtener la URI correcta.
  • ✏️ Sustituye usuario, contraseña y base de datos.
  • 📁 Guárdala en tu archivo .env.
  • 🚀 Con dotenv podrás acceder a tus variables con process.env.
  • 🧩 ¡Lista para usarla en db.js y conectar con Mongoose!

🚫 Paso 2. Crear el archivo .gitignore

El archivo .gitignore indica a Git qué archivos o carpetas no deben subirse al repositorio (por ejemplo, a GitHub). Su objetivo es proteger información sensible y evitar subir archivos innecesarios que solo sirven en tu entorno local.

💡 ¿Por qué es importante?

  • 🔒 Protege tus credenciales y datos sensibles (por ejemplo, el archivo .env con la contraseña de tu base de datos).
  • ⚙️ Evita subir carpetas pesadas como node_modules/ (que se pueden volver a generar con npm install).
  • 🧹 Mantiene tu repositorio limpio, ligero y seguro.

💡 Recuerda: Git solo ignora los archivos que se añadan al .gitignore antes de haber sido commiteados. Si ya subiste un archivo sensible por error, deberás eliminarlo del historial del repositorio.

📄 Cómo crear el archivo

  1. En la raíz del proyecto (donde está tu package.json), crea un archivo nuevo llamado .gitignore.
  2. Pega dentro el siguiente contenido mínimo recomendado:
# Ignorar dependencias (carpeta generada por npm)
node_modules/

# Ignorar variables de entorno (credenciales y configuraciones)
.env

# Ignorar archivos temporales o de sistema
.DS_Store
Thumbs.db

# Ignorar logs de ejecución
npm-debug.log*
yarn-debug.log*
yarn-error.log*

✅ Explicación rápida:

  • node_modules/: contiene todas las dependencias instaladas con npm. No se sube a Git porque puede regenerarse con npm install añade esta explicación en tu README
  • .env: archivo con datos sensibles (URI de MongoDB, claves, puertos).
  • .DS_Store y Thumbs.db: archivos ocultos de macOS y Windows.
  • *.log: registros de errores o depuración generados durante la ejecución.
⚠️ Importante: Si olvidaste añadir .env al .gitignore y ya hiciste commit, elimínalo del repositorio inmediatamente con: 
git rm --cached .env
Luego haz un nuevo commit para asegurar que queda fuera del control de versiones.
💬 Consejo: Puedes usar una plantilla oficial de GitHub para Node.js si quieres ampliar tu configuración según tu entorno o editor.

🎯 Objetivo: Con este archivo, tu proyecto estará seguro y limpio. Git solo subirá el código esencial y dejará fuera todo lo que no debe compartirse.

⚙️ 3. Creando el archivo de conexión db.js

Este archivo se guarda dentro de la carpeta src/config/ y se encarga de conectar nuestra aplicación con la base de datos. Lo hacemos con la librería Mongoose, que simplifica las conexiones y gestiona automáticamente la reconexión si se pierde la conexión con Atlas. 

// src/config/db.js
import mongoose from "mongoose";

export async function connectDB() {
  try {
    // 1️⃣ Leemos la URI completa y el nombre de la base desde el archivo .env
    const uri = process.env.MONGODB_URI;
    const dbName = process.env.MONGODB_DB || "tienda";

    if (!uri) {
      console.error("❌ No se encontró la variable MONGODB_URI en el archivo .env");
      process.exit(1);
    }

    // 2️⃣ Intentamos establecer la conexión con Mongoose
    await mongoose.connect(uri, {
      dbName,
      autoIndex: true, // crea índices si los defines en tus Schemas
    });

    console.log(`✅ Conectado a MongoDB → Base de datos: ${dbName}`);
  } catch (error) {
    console.error("❌ Error al conectar con MongoDB:", error.message);
    process.exit(1); // Detiene el servidor si no puede conectar
  }
}

💬 ¿Qué hace este código paso a paso?

  • 1️⃣ Importa Mongoose, la librería que gestiona las conexiones con MongoDB.
  • 2️⃣ Obtiene la cadena de conexión (MONGODB_URI) desde el archivo .env.
  • 3️⃣ Llama a mongoose.connect() para establecer la conexión.
  • 4️⃣ Si todo va bien, muestra un mensaje de éxito en la consola.
  • 5️⃣ Si algo falla (URI incorrecta, red caída, credenciales erróneas…), muestra un error claro y detiene el servidor.

🎯 Objetivo: Tener una función reutilizable (connectDB()) que puedas importar en server.js para que la conexión a MongoDB se realice automáticamente al arrancar el servidor.

🚀 4️⃣ Conectando la base de datos en server.js

El archivo server.js es el corazón del servidor. Aquí importamos la función connectDB() para que la base de datos se conecte antes de iniciar el servidor Express. 

// src/server.js
import express from 'express';
import cors from 'cors';
import dotenv from 'dotenv';
import { connectDB } from './config/db.js';
import productosRoutes from './routes/productos.js';

dotenv.config(); // carga el archivo .env

const app = express();
app.use(cors());
app.use(express.json());

// Conectar a MongoDB
await connectDB();

// Rutas principales
app.use('/api/productos', productosRoutes);

// Ruta de prueba
app.get('/', (_req, res) => res.json({ ok: true }));

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => {
  console.log(`🚀 Servidor corriendo en http://localhost:${PORT}`);
});

🧩 ¿Cómo ver estos mensajes en la consola?

Para comprobar que tu servidor y la base de datos están funcionando correctamente, debes arrancar el servidor Node.js desde la terminal de Visual Studio Code.

⚙️ Pasos para iniciar el servidor

  1. Abre la Terminal integrada en VS Code (Ctrl + Ñ o Ctrl + Shift + ').
  2. Comprueba que estás dentro de la carpeta backend-mongoose o similar.
  3. Ejecuta el comando: 
    npm run dev

    💡 Si no tienes nodemon instalado, también puedes usar:

    node src/server.js
  4. Espera unos segundos ⏳ hasta que aparezcan los mensajes de éxito.

🎯 Ejemplo de salida correcta:

[dotenv@17.2.3] injecting env (3) from .env
✅ Conectado a MongoDB → Base de datos: tienda
🚀 Servidor corriendo en http://localhost:3000

📘 Significado de los mensajes:

  • ✅ Conectado a MongoDB: Mongoose ha establecido conexión con tu base de datos Atlas.
  • 🚀 Servidor corriendo: Express está funcionando y escuchando peticiones HTTP en el puerto configurado (por defecto 3000).

🎉 Enhorabuena: Si ves ambos mensajes, tu backend está completamente operativo. Ya puedes probar tus rutas con Thunder Client, Postman o conectar el frontend React.

🧩 5️⃣ Entendiendo el flujo completo

Veamos cómo encajan todas las piezas: 

server.js → importa connectDB() → lee .env → se conecta a MongoDB Atlas → 
Rutas (productosRoutes) → Controladores → Modelos → Base de datos

📘 En resumen:

  • .env guarda las credenciales.
  • db.js establece la conexión segura.
  • server.js arranca el servidor y activa las rutas.

✅ Ya tienes una API real conectada a MongoDB Atlas.
