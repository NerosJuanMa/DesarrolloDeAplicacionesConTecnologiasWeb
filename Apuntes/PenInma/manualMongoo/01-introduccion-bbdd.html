Tema 1

¿Qué es una base de datos?

Manual didáctico: definición, utilidad, tipos, ejemplos, buenas prácticas y ejercicios — enfoque Full Stack.

⬅ Volver al índice Siguiente tema ➜

¿Qué es este manual?

Es una introducción a “Mongoo” (base de datos no relacional orientada a documentos). El objetivo es que comprendas los fundamentos de las bases de datos relacionales y no relacionales y sepas aplicar ambos enfoques en desarrollo web.

📚 Base de datos vs. Gestor de base de datos

Aunque a menudo se confunden, una base de datos y un gestor de base de datos no son lo mismo. Entender esta diferencia es clave antes de empezar a trabajar con MySQL o MongoDB.

🧠 Base de datos

Es el conjunto estructurado de información que almacenamos para que pueda ser consultada o modificada. Piensa en ella como una biblioteca digital: las estanterías serían las tablas o colecciones, y los libros serían los registros o documentos.

Su función es guardar los datos de forma organizada, coherente y accesible. Puede estar guardada en un servidor local o en la nube (como en MongoDB Atlas).

⚙️ Gestor de base de datos (SGBD)

Es el programa o sistema que permite crear, modificar, consultar y administrar la base de datos. Es decir, el gestor es la herramienta que maneja el contenido de la base de datos.

  • Ejemplos relacionales: MySQL, PostgreSQL, SQLite.
  • Ejemplos no relacionales (NoSQL): MongoDB, CouchDB, Firebase.

Sin un gestor, los datos serían simples archivos difíciles de manipular. El SGBD proporciona lenguajes de consulta (como SQL o las consultas de MongoDB) y seguridad en el acceso.

📊 Resumen comparativo

Concepto Función principal Ejemplo
Base de datos Contiene los datos organizados. Biblioteca con fichas de usuarios o productos.
Gestor de base de datos Administra y controla el acceso a esos datos. MySQL, MongoDB, Oracle, SQLite.

Objetivos de aprendizaje

  • Comprender el concepto de base de datos.
  • Distinguir entre modelos relacionales y NoSQL.
  • Aprender los fundamentos de “Mongoo” y su relación con MySQL.
  • Instalar el entorno y crear la primera colección de datos.
  • Aplicar operaciones CRUD con ejemplos didácticos.
  • Desarrollar un mini-proyecto final comparando MongoDB y MySQL.

3️⃣ ¿Qué aporta al desarrollo Full Stack?

  • Persistencia real de datos en producción.
  • Backend sólido (API/servicios) que conversa con el frontend.
  • Escalabilidad y profesionalización del proyecto.

4️⃣ Alternativas a las BBDD

  • Archivos JSON / texto plano.
  • Variables en memoria (se pierden al reiniciar).
  • Hojas de cálculo.
  • APIs externas como “fuente de datos”.

Útiles para prototipos o proyectos pequeños, pero no sustituyen a una BBDD en robustez, seguridad y escalabilidad.

5️⃣ Tipos de bases de datos

Internas vs Externas

  • Internas (embebidas): p. ej. SQLite (un solo archivo, sin servidor).
  • Externas (cliente-servidor): MySQL, PostgreSQL, MongoDB…

Relacionales vs No relacionales

  • Relacionales (SQL): tablas, filas y columnas con tipos rígidos.
  • No relacionales (NoSQL): documentos (JSON), clave-valor, grafos o columnas anchas.

7️⃣ Filas/Columnas (SQL) vs Documentos/Claves (NoSQL)

Relacional (SQL)

  • Columnas = campos tipados.
  • Filas = registros con la misma estructura.
Tabla de ejemplo con alumnos
idnombreedadciudad
1Ana López20Sevilla
2Luis Díaz22Madrid
3Marta Gil21Valencia

No relacional (Documentos)

[
  { "_id": 1, "nombre": "Ana López", "edad": 20, "ciudad": "Sevilla" },
  { "_id": 2, "nombre": "Luis Díaz", "correo": "luis@example.com", "activo": true }
]
Observa: los documentos pueden tener campos diferentes entre sí. Esta flexibilidad agiliza el desarrollo, pero exige buenas prácticas de validación.

⚖️ ACID vs BASE: dos enfoques

Dos filosofías para gestionar datos según la prioridad del sistema.

🛡️ ACID (banca, transacciones críticas)

  • Atomicidad: todo o nada.
  • Consistencia: reglas siempre válidas.
  • Aislamiento: operaciones no se interfieren.
  • Durabilidad: lo confirmado persiste.

Resultado: máxima fiabilidad. Ideal para operaciones monetarias, inventarios estrictos, etc.

🚀 BASE (alta disponibilidad y escala)

  • Básicamente disponible: el sistema rara vez cae.
  • Estado suave: los datos pueden cambiar “en tránsito”.
  • Consistencia eventual: todo converge tras unos segundos.

Resultado: gran rendimiento y escalabilidad. Ideal para redes sociales, streaming, IoT.

Conclusión: ¿Necesitas exactitud perfecta? prioriza ACID. ¿Prioridad rendimiento/escala? adopta BASE.

🧱 Normalización vs Desnormalización

Elegimos entre evitar duplicidad (normalizar) o acelerar lecturas (desnormalizar).

📐 Normalización (SQL)

  • Cada dato se guarda una sola vez (menos errores).
  • Actualizar un dato afecta a todas las consultas.
  • Lecturas más lentas por joins entre tablas.

📦 Desnormalización (NoSQL)

  • Se duplican datos a propósito para leer más rápido.
  • Actualizaciones más costosas (varios documentos).
  • Rendimiento de lectura alto con menos “joins”.

9️⃣ Ejemplos prácticos: SQL vs Mongo

SQL (MySQL/PostgreSQL)

-- Crear tabla
CREATE TABLE alumnos (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  edad INT,
  ciudad VARCHAR(80)
);

-- Insertar
INSERT INTO alumnos (nombre, edad, ciudad)
VALUES ('Ana López', 20, 'Sevilla');

-- Consultar
SELECT id, nombre, ciudad
FROM alumnos
WHERE edad >= 20;

MongoDB (documentos)

// Insertar varios
db.alumnos.insertMany([
  { nombre: "Ana López", edad: 20, ciudad: "Sevilla" },
  { nombre: "Luis Díaz", correo: "luis@example.com" }
]);

// Consultar (filtro y proyección)
db.alumnos.find(
  { edad: { $gte: 20 } },
  { nombre: 1, ciudad: 1 }
);

// Actualizar
db.alumnos.updateOne(
  { nombre: "Ana López" },
  { $set: { ciudad: "Córdoba" } }
);

Diferencia clave: en SQL defines el esquema antes de guardar; en Mongo puedes empezar flexible y validar con el tiempo.

❓ Preguntas frecuentes (FAQ)

¿Puedo empezar con JSON y migrar después?

Sí. Prototipa con JSON y migra a SQL/Mongo cuando el proyecto crezca.

¿SQL es “mejor” que NoSQL?

Depende del caso de uso: SQL prioriza integridad; NoSQL prioriza flexibilidad y escalado.

¿Qué elijo para mi primer CRUD?

Si hay relaciones/consultas complejas, SQL. Para iterar rápido con front-end JS, Mongo es excelente.
