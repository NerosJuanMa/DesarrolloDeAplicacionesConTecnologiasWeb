🏠 Inicio Siguiente tema ➜

📦 1️⃣ Colección y 📄 2️⃣ Documento: Los Protagonistas

📦 La Colección (Tu Carpeta de Datos)

Una Colección es el contenedor lógico de documentos. Es el equivalente a una Tabla SQL, pero con una diferencia CLAVE: los documentos dentro no tienen por qué tener la misma estructura.

  • Ejemplo: La colección se llamará `productos`.
  • Sintaxis: Siempre la nombras en minúsculas y plural, siguiendo la convención de la comunidad (ej. `db.productos`).

📄 El Documento (Tu Dato Completo)

Un Documento es el registro individual, un objeto escrito en formato JSON (o BSON en memoria). Es la Fila de SQL, pero con campos flexibles.

Ejemplo: Producto (Documento en la colección `productos`)

{
  "nombre": "Camiseta React",
  "precio": 19.99,
  "stock": 50,
  "categoria": "ropa",
  "activo": true
}

🧱 Crear una Base de Datos, Colecciones y Documentos

En MongoDB no necesitas crear manualmente las bases de datos. El sistema aplica el principio de creación perezosa (lazy creation): la base de datos y sus colecciones se generan automáticamente cuando insertas el primer documento.

⚙️ 1️⃣ Cambiar de contexto con use <nombre>

El comando use permite moverte al contexto de una base de datos existente o preparar una nueva. Si no existe aún, MongoDB la mantiene en espera hasta que insertes algo. 

// Cambiar o preparar el contexto de la base "tienda"
use tienda
Nota: Tras ejecutar use tienda la base todavía no aparece en show dbs. Solo será visible cuando contenga al menos un documento.

⚙️ 2️⃣ Crear la primera colección e insertar un documento

En MongoDB, las colecciones son el equivalente a las tablas en SQL. Se crean automáticamente al insertar el primer documento dentro de ellas: 

// Crear colección "productos" e insertar un documento
db.productos.insertOne({
  nombre: "Camiseta básica",
  precio: 9.99,
  stock: 50,
  categoria: "ropa"
})

Este comando crea tres niveles de estructura:

  • 🗄️ Base de datos tienda
  • 📁 Colección productos
  • 📄 Documento con campos nombre, precio, stock y categoria

🧩 3️⃣ Añadir más colecciones

Puedes crear nuevas colecciones de la misma manera, simplemente insertando documentos en ellas: 

// Crear colección "clientes"
db.clientes.insertOne({
  nombre: "Lucía Pérez",
  email: "lucia@example.com",
  ciudad: "Madrid"
})

// Crear colección "pedidos"
db.pedidos.insertOne({
  cliente: "Lucía Pérez",
  producto: "Camiseta básica",
  cantidad: 2,
  fecha: new Date()
})
Resumen:
  • use tienda → cambia al contexto o crea el espacio de trabajo.
  • insertOne() → crea la colección y el primer documento.
  • Las colecciones se crean automáticamente al insertar datos.
  • MongoDB crea la base de datos cuando guardas el primer documento.

🔗 4️⃣ Relaciones entre colecciones

Aunque MongoDB no usa claves foráneas como en SQL, podemos establecer relaciones lógicas entre colecciones enlazando documentos mediante campos comunes (por ejemplo, el _id del cliente dentro de un pedido). Esto se llama referencia o embedding. 

// Ejemplo de referencia (cliente relacionado en pedidos)
db.pedidos.insertOne({
  clienteId: ObjectId("673b2a9c12345abcde67890f"), // _id del cliente
  producto: "Camiseta básica",
  cantidad: 2
})
En resumen: una base de datos MongoDB se forma por colecciones, y cada colección contiene documentos JSON independientes que pueden relacionarse entre sí mediante campos comunes o identificadores.

Clave: insertar el primer documento crea BBDD y colección.

🔗 Relaciones entre colecciones

En MongoDB puedes relacionar datos de dos maneras principales: Embedding (anidando documentos) y Referencias (enlazando mediante _id).

🧩 Embedding (anidar)

Consiste en guardar subdocumentos dentro del documento principal. Es útil cuando los datos siempre se consultan juntos, por ejemplo, las líneas de un pedido.

// Un pedido con sus líneas embebidas
db.pedidos.insertOne({
  cliente: { _id: ObjectId("..."), nombre: "Lucía" },
  lineas: [
    { productoId: ObjectId("..."), nombre: "Camiseta", cantidad: 2 },
    { productoId: ObjectId("..."), nombre: "Pantalón", cantidad: 1 }
  ],
  fecha: new Date()
})
Útil para: lecturas rápidas y estructuras simples donde los datos “viven y mueren” juntos.

🔗 Referencias (_id)

En lugar de duplicar datos, guardamos solo los identificadores de otros documentos, estableciendo una relación lógica entre colecciones.

// Un pedido que referencia cliente y productos
db.pedidos.insertOne({
  clienteId: ObjectId("64f...abc"),
  productoIds: [ ObjectId("65a...def"), ObjectId("65a...987") ],
  fecha: new Date()
})
Útil para: evitar duplicados, mantener integridad y reducir el tamaño de los documentos cuando los datos cambian con frecuencia.

🧮 ¿Cuál usar?

Elige el tipo de relación en función del tamaño, frecuencia de actualización y reutilización de los datos.

Caso Mejor opción
Datos pequeños y muy ligados ✅ Embedding
Reutilización en muchas colecciones ✅ Referencias
Actualizaciones frecuentes ✅ Referencias
Lectura única “todo en uno” ✅ Embedding
Regla práctica: usa embedding cuando los datos sean inseparables y se consulten juntos; usa referencias cuando se compartan, crezcan o cambien a menudo.
Resumen visual: 🗄️ BBDD → 📁 Colecciones → 📄 Documentos → 🔗 Relaciones (Embedding / Referencias).

🧪 3️⃣ El CRUD: Creación de Datos (INSERT)

La operación de Creación (CREATE) o Inserción (INSERT) es el primer paso. Aquí es donde debes prestar más atención a la sintaxis del Shell.

La Sintaxis de Oro del MongoDB Shell

Todos los comandos que verás aquí y en el resto del CRUD siguen este patrón:

db.nombreColeccion.metodo(argumentos)
  • db: palabra reservada que representa tu Base de Datos actual. ¡Siempre empieza por db!
  • .nombreColeccion: carpeta donde guardarás el dato (ej. .productos).
  • .metodo(): la acción (ej. .insertOne()).

Importante: ¿Cuándo se Crea la Colección?

¡Atención! En MongoDB, NO necesitas un CREATE COLLECTION. La colección se crea de forma implícita en el momento en que insertas el primer documento.

Método 1: Inserción de un Único Documento (insertOne)

Utiliza este método para añadir un solo documento. El argumento es el objeto JSON que quieres guardar.

// Insertar UN documento en la colección 'productos'
db.productos.insertOne({
  nombre: "Auriculares Bluetooth",
  precio: 35.0,
  stock: 100,
  categoria: "tecnologia",
  activo: true
});

Método 2: Inserción de Varios Documentos (insertMany)

Más eficiente cuando quieres añadir varios documentos de golpe. El argumento es un array [] con objetos JSON.

// Insertar VARIOS documentos en la colección 'productos'
db.productos.insertMany([
  { nombre: "Camiseta React", precio: 19.99, stock: 50,  categoria: "ropa" },
  { nombre: "Taza JavaScript", precio: 9.5,  stock: 120, categoria: "accesorios" }
]);

🔍 4️⃣ El RUD: Leer (Buscar) Documentos

La lectura de datos se realiza con el método .find(), equivalente al SELECT de SQL. Es una de las operaciones más usadas en MongoDB, ya que permite explorar, filtrar y ordenar los documentos almacenados.

📘 Sintaxis general

db.coleccion.find(filtro, proyeccion)
  • filtro: define qué documentos quieres recuperar. Si lo dejas vacío, devuelve todos.
  • proyección: indica qué campos mostrar (por defecto muestra todos).

📜 Buscar TODO (equivalente a SELECT *)

db.productos.find()
// Si dejas los paréntesis vacíos, muestra todos los documentos.

🎯 Buscar con Filtro (el WHERE)

db.productos.find({ activo: true })
// Busca todos los productos donde el campo 'activo' sea true.

🎛️ Proyección de campos

Para mostrar solo ciertos campos (como en SELECT nombre, precio FROM ...):

// Muestra solo nombre y precio, sin el campo _id
db.productos.find({}, { nombre: 1, precio: 1, _id: 0 })

🔢 Operadores de comparación

MongoDB utiliza operadores con prefijo $ para realizar comparaciones dentro de los filtros. Funcionan igual que los signos matemáticos (<, ≤, >, ≥, =, ≠), pero adaptados a la sintaxis JSON. 

// Precio MENOR o IGUAL que 20
db.productos.find({ precio: { $lte: 20 } })

// Precio MAYOR que 30
db.productos.find({ precio: { $gt: 30 } })

// Precio ENTRE 10 y 25
db.productos.find({ precio: { $gte: 10, $lte: 25 } })

📘 Significado de los operadores

Operador Significado Ejemplo Equivalente matemático
$eq Igual a { precio: { $eq: 10 } } =
$ne No igual a { precio: { $ne: 10 } } ≠
$lt Menor que { precio: { $lt: 20 } } <
$lte Menor o igual que { precio: { $lte: 20 } } ≤
$gt Mayor que { precio: { $gt: 30 } } >
$gte Mayor o igual que { precio: { $gte: 30 } } ≥
💡 Consejo: Puedes combinar varios operadores en el mismo filtro para crear consultas más precisas, por ejemplo: 
db.productos.find({ precio: { $gte: 10, $lte: 25 } })
Esto devuelve los productos con precios comprendidos entre 10 y 25 (ambos incluidos).
Resumen rápido:
  • $lt → menor que (less than)
  • $lte → menor o igual que (less than or equal)
  • $gt → mayor que (greater than)
  • $gte → mayor o igual que (greater than or equal)
  • $eq → igual a (equal)
  • $ne → distinto de (not equal)
🗣️ Etimología: Todos los operadores son abreviaturas del inglés:
  • lt → less than (menor que)
  • lte → less than or equal (menor o igual que)
  • gt → greater than (mayor que)
  • gte → greater than or equal (mayor o igual que)
  • eq → equal (igual)
  • ne → not equal (no igual)

📊 Ordenar, limitar y paginar

Como en SQL con ORDER BY y LIMIT, puedes controlar el orden y número de resultados.

// Orden ascendente por precio (1 = ascendente, -1 = descendente)
db.productos.find().sort({ precio: 1 })

// Limitar resultados
db.productos.find().limit(5)

// Saltar los primeros N documentos (paginación)
db.productos.find().sort({ precio: 1 }).skip(5).limit(5)

🧮 Contar documentos

Para saber cuántos documentos cumplen un filtro:

// Contar todos los documentos
db.productos.countDocuments({})

// Contar solo los activos
db.productos.countDocuments({ activo: true })

// Contar los de una categoría concreta
db.productos.countDocuments({ categoria: "ropa" })
💡 Tip profesional: Combina find() con sort(), limit() y countDocuments() para inspeccionar grandes colecciones sin sobrecargar la consola ni el servidor.
🧩 Equivalencias SQL ↔ MongoDB
SQL MongoDB
SELECT * FROM productos db.productos.find()
SELECT nombre, precio FROM productos db.productos.find({}, { nombre: 1, precio: 1, _id: 0 })
SELECT * FROM productos WHERE precio > 30 db.productos.find({ precio: { $gt: 30 } })
SELECT * FROM productos ORDER BY precio ASC LIMIT 5 db.productos.find().sort({ precio: 1 }).limit(5)

✏️ 5️⃣ El CUD: Actualizar Documentos

Actualizar datos significa modificar el valor de uno o varios campos de un documento existente. En MongoDB lo hacemos con los métodos updateOne() y updateMany(). Siempre debes indicar **qué documento** quieres cambiar (filtro) y **cómo** quieres cambiarlo (operador).

🧩 Sintaxis general

db.coleccion.updateOne(filtro, { operador: { cambios } })
  • filtro: indica qué documento(s) se van a modificar (por ejemplo { nombre: "Taza JS" }).
  • operador: define cómo cambiar los valores ($set, $inc, $push...).
💡 Recuerda: si no usas un operador (como $set), reemplazarás todo el documento por el nuevo objeto.

Actualizar UNO (updateOne)

Modifica solo el primer documento que cumpla el filtro.

db.productos.updateOne(
  { nombre: "Taza JavaScript" },   // Filtro
  { $set: { precio: 10.00 } }      // Operador: cambia el precio a 10.00
)

Actualizar VARIOS (updateMany)

Modifica todos los documentos que cumplan el filtro.

db.productos.updateMany(
  { categoria: "ropa" }, 
  { $inc: { stock: 10 } } // Suma 10 unidades al stock de toda la ropa
)

🔧 Principales Operadores de Actualización

  • $set → Asigna un nuevo valor a un campo existente o lo crea si no existe.
  • $inc → Incrementa (suma o resta) el valor numérico de un campo.
  • $push → Agrega un valor al final de un array (permite duplicados).
  • $addToSet → Agrega un valor al array solo si no existe (sin duplicar).
// Ejemplos de uso de operadores
db.productos.updateOne(
  { nombre: "Sudadera Dev" },
  { $addToSet: { tallas: "XL" } } // añade una talla sin duplicar
)

db.productos.updateOne(
  { nombre: "Sudadera Dev" },
  { $push: { tallas: "XS" } }     // añade talla al final del array
)

🚀 Crear si no existe (Upsert)

Si el documento no existe, MongoDB puede crearlo automáticamente con la opción { upsert: true }.

db.productos.updateOne(
  { nombre: "Gorra Node" },
  { $set: { precio: 14.5, stock: 25, categoria:"accesorios", activo:true } },
  { upsert: true }
)

🧨 Reemplazar un documento completo

Con replaceOne() sustituyes todo el documento por otro nuevo (se mantiene el mismo _id).

db.productos.replaceOne(
  { nombre: "Pegatina CSS" },
  { nombre: "Pegatina CSS", precio: 1.75, stock: 250, categoria:"accesorios", activo:true }
)

📋 Verificar los cambios

Después de actualizar, revisa los resultados con una consulta:

db.productos.find({}, { nombre: 1, precio: 1, stock: 1, _id: 0 })
Checkpoint:
  • ¿Se actualizó el precio correctamente?
  • ¿Los productos de ropa aumentaron su stock?
  • ¿Aparece el nuevo campo o array si antes no existía?

⚙️ Comparativa con Mongoose (nivel profesional)

En código (Node.js + Mongoose) usarás los mismos métodos, pero aplicados a un modelo. Ambos ejemplos realizan la misma operación, solo cambia el entorno donde se ejecutan:

💻 En Shell

db.productos.updateOne(
  { nombre:"Taza JS" },
  { $set:{ precio:12.99 } }
)

🧠 En Mongoose

await Producto.updateOne(
  { nombre:"Taza JS" },
  { $set:{ precio:12.99 } }
)
💡 ¿Por qué usamos await en Mongoose?

Porque updateOne() devuelve una Promesa. Node.js ejecuta el código de manera asíncrona y no espera automáticamente a que termine la operación con la base de datos. Al escribir await, indicamos al programa que se detenga hasta recibir la respuesta, garantizando que los cambios se guarden antes de continuar.

En Mongoose también podrás usar métodos equivalentes como .findByIdAndUpdate() o .save() para manejar la lógica desde el backend. Lo importante es que ahora entiendes qué está ocurriendo dentro de la base de datos.

Resumen:
  • Usa updateOne() o updateMany() con operadores de cambio ($set, $inc, $push...).
  • Utiliza upsert para crear el documento si no existe.
  • Comprueba siempre los resultados con find() o countDocuments().
  • En Mongoose, el mismo proceso se traduce a métodos de modelo.

🗑️ 6️⃣ El CRD: Borrar Documentos

El borrado de documentos es la operación más delicada del CRUD. En MongoDB se realiza con los métodos deleteOne() y deleteMany(). Recuerda: no hay vuelta atrás, así que revisa siempre tu filtro antes de ejecutar.

🧩 Sintaxis general

db.coleccion.deleteOne(filtro)
db.coleccion.deleteMany(filtro)
  • deleteOne() → elimina solo el primer documento que cumpla el filtro.
  • deleteMany() → elimina todos los documentos que cumplan el filtro.
  • Si no incluyes filtro, podrías eliminar toda la colección (¡peligroso!).
⚠️ Consejo crítico: Antes de borrar, ejecuta siempre un find() con el mismo filtro para comprobar qué documentos se verán afectados.

🗑️ Borrar UNO (deleteOne)

Elimina el primer documento que cumpla el filtro especificado.

// Ejemplo: borrar un solo producto
db.productos.deleteOne({ nombre: "Camiseta React" })

✅ Ideal para eliminar un elemento concreto (por su nombre, ID o campo único).

🧹 Borrar VARIOS (deleteMany)

Elimina todos los documentos que coincidan con el filtro.

// Ejemplo: borrar todos los productos inactivos
db.productos.deleteMany({ activo: false })

⚠️ Úsalo con precaución: revisa tu filtro o limita el borrado a colecciones de prueba.

🔎 Verificar resultados

Después de un borrado, puedes comprobar cuántos documentos quedan:

db.productos.countDocuments({})
// o verificar directamente los activos
db.productos.find({ activo: true }, { nombre:1, _id:0 })

🧱 Casos prácticos

  • Eliminar productos obsoletos o descatalogados:
    • db.productos.deleteMany({ stock: { $lte: 0 } })
  • Eliminar un documento por su _id (ID único):
    • db.productos.deleteOne({ _id: ObjectId("654e3a8e14c0d4e4f5c17a3b") })

💾 Precauciones adicionales

  • Haz siempre una copia o exportación antes de borrados masivos (mongoexport).
  • No uses deleteMany({}) salvo en entornos de práctica o test.
  • Para limpiar una colección completa de forma controlada, puedes hacerlo desde la consola de Atlas (con confirmación manual).

⚙️ Comparativa con Mongoose

En Shell

db.productos.deleteOne({ nombre: "Camiseta React" })
db.productos.deleteMany({ activo: false })

En Mongoose

await Producto.deleteOne({ nombre: "Camiseta React" })
await Producto.deleteMany({ activo: false })

En Mongoose también podrás usar métodos derivados como findByIdAndDelete() o deleteMany() directamente sobre el modelo. La lógica es la misma: se traduce internamente al comando MongoDB equivalente.

⚠️ Advertencia final: El borrado no se puede deshacer. Antes de ejecutar un deleteMany(), verifica tu filtro, haz una copia y confirma que estás en la base de datos correcta.

🧾 8️⃣ Nueva colección: pedidos

Ahora que ya sabes crear colecciones y documentos, es momento de dar un paso más: relacionar los datos entre sí. Crearemos una colección pedidos donde cada documento estará vinculado con un cliente y uno o varios productos.

Objetivo didáctico: Comprender cómo se conectan las colecciones entre sí usando ObjectId (referencias) o subdocumentos embebidos.

📁 1️⃣ Crear la colección clientes (si no existe)

Primero necesitamos algunos clientes en nuestra base de datos. Si aún no los tienes, crea unos pocos ejemplos en la colección clientes: 

// Crear algunos clientes
db.clientes.insertMany([
  { nombre: "Lucía Pérez", email: "lucia@example.com", ciudad: "Madrid" },
  { nombre: "Carlos López", email: "carlos@example.com", ciudad: "Sevilla" }
])

📦 2️⃣ Crear la colección productos (si no existe)

De igual forma, asegúrate de tener productos disponibles en la colección productos:

// Crear algunos productos de ejemplo
db.productos.insertMany([
  { nombre: "Camiseta React", precio: 19.99, stock: 50, categoria: "ropa", activo: true },
  { nombre: "Taza JavaScript", precio: 9.5, stock: 120, categoria: "accesorios", activo: true }
])

🧩 3️⃣ Crear la colección pedidos (con referencias)

Para relacionar las colecciones, obtenemos primero los _id de un cliente y de los productos. Luego los usamos como referencias dentro del pedido: 

// Buscar un cliente y un producto
const cliente = db.clientes.findOne({ email: "lucia@example.com" })
const producto1 = db.productos.findOne({ nombre: "Camiseta React" })
const producto2 = db.productos.findOne({ nombre: "Taza JavaScript" })

// Crear un pedido referenciando cliente y productos
db.pedidos.insertOne({
  clienteId: cliente._id,
  productos: [
    { productoId: producto1._id, cantidad: 2 },
    { productoId: producto2._id, cantidad: 1 }
  ],
  fecha: new Date(),
  estado: "pendiente",
  total: producto1.precio * 2 + producto2.precio
})
¿Qué acabas de hacer?
  • 🗄️ Has creado una nueva colección: pedidos.
  • 🔗 Has relacionado documentos usando ObjectId como referencia.
  • 🧮 Has calculado un campo total a partir de los precios.

🧩 4️⃣ Alternativa: Embedding (subdocumentos)

Si el pedido no va a crecer mucho y quieres guardar todo “junto”, puedes embebir los datos directamente dentro del documento principal: 

// Pedido con datos embebidos
db.pedidos.insertOne({
  cliente: { nombre: "Carlos López", email: "carlos@example.com" },
  productos: [
    { nombre: "Camiseta React", cantidad: 1, precio: 19.99 },
    { nombre: "Taza JavaScript", cantidad: 2, precio: 9.5 }
  ],
  fecha: new Date(),
  estado: "enviado",
  total: 19.99 + 2 * 9.5
})
Embedding vs Referencias:
  • Embedding = todo el pedido está contenido en un único documento (rápido de leer).
  • Referencias = las relaciones se mantienen separadas y actualizables.

📋 5️⃣ Comprobación de datos

Para visualizar los pedidos creados:

db.pedidos.find().pretty()
Resumen de este bloque:
  • ✅ clientes → colección con datos personales.
  • ✅ productos → colección con el catálogo.
  • ✅ pedidos → colección que relaciona ambas mediante ObjectId o documentos embebidos.
  • 🧠 Entiendes cómo MongoDB maneja relaciones sin usar claves foráneas.

🌟 10 Métodos Fundamentales: La Guía Rápida del CRUD

Estos son los comandos esenciales que debes memorizar. Son la base de las operaciones en MongoDB, tanto si trabajas directamente en la consola (Shell) como si programas con Mongoose. Hay muchos más y muchos más operadores pero recuerda que Roma no se construyó en una semana. Empieza por dominar estos y luego ve ampliando tu repertorio.

CRUD Función Sintaxis en MongoDB Shell (Prueba) Sintaxis en Mongoose (Profesional)
CREAR (INSERTAR)
CREATE Inserta un documento. db.productos.insertOne({ ... }) await Producto.create({ ... })
CREATE Inserta varios documentos a la vez. db.productos.insertMany([ {..}, {..} ]) await Producto.insertMany([ {..}, {..} ])
READ (LEER / BUSCAR)
READ Busca uno o más documentos (el SELECT básico). db.productos.find( {filtro} ) Modelo.find( {filtro} )
READ Busca solo el primer documento que coincida. db.productos.findOne( {filtro} ) Modelo.findOne( {filtro} )
UPDATE (ACTUALIZAR)
UPDATE Actualiza solo el primer documento que coincida. db.productos.updateOne( {filtro}, {$set: {..}} ) Modelo.updateOne( {filtro}, {$set: {..}} )
UPDATE Actualiza todos los documentos que coincidan. db.productos.updateMany( {filtro}, {$inc: {..}} ) Modelo.updateMany( {filtro}, {$inc: {..}} )
DELETE (BORRAR)
DELETE Borra solo el primer documento que coincida. db.productos.deleteOne( {filtro} ) Modelo.deleteOne( {filtro} )
DELETE Borra todos los documentos que coincidan. db.productos.deleteMany( {filtro} ) Modelo.deleteMany( {filtro} )
UTILIDAD ESENCIAL
COUNT Cuenta cuántos documentos cumplen un filtro. db.productos.countDocuments( {filtro} ) Modelo.countDocuments( {filtro} )

Recuerda la clave: En el Shell usas db.nombre_coleccion. En Mongoose (código) usas Modelo (con mayúscula y singular, por convención, como Producto).

🧭 Ejercicio guiado — Crea tu BD en Atlas y haz un CRUD completo desde la consola

Objetivo: conectarte a tu cluster de MongoDB Atlas con mongosh, crear tu base de datos tienda, trabajar con la colección productos y practicar INSERT, READ, UPDATE y DELETE con datos realistas (tipos simples, documentos embebidos y arrays).

Requisitos previos: tener tu usuario de base de datos creado en Atlas, la IP permitida, y mongosh instalado. Si no, revisa las secciones 2.1–2.4 de este tema.

Paso 1 — Conéctate a tu cluster y selecciona la base

  1. Abre tu terminal (PowerShell en Windows o tu terminal habitual).
  2. Conéctate a Atlas (la contraseña se pide de forma segura):
mongosh "mongodb+srv://<TU_CLUSTER>.mongodb.net/tienda" --username "<TU_USUARIO>"

Si no pusiste la base en la URI, selecciónala ahora:

use tienda
show collections

Al principio puede que no haya colecciones; se crean al insertar el primer documento.

Paso 2 — INSERT: crea la colección y añade documentos

Vamos a trabajar con db.productos. La colección se crea al primer insert.

2.1 Insertar 1 documento (simple)

db.productos.insertOne({
  nombre: "Camiseta React",
  precio: 19.99,
  stock: 50,
  categoria: "ropa",
  activo: true
})

2.2 Insertar varios (tipos variados)

db.productos.insertMany([
  {
    nombre: "Taza JavaScript",
    precio: 9.5,
    stock: 120,
    categoria: "accesorios",
    activo: true
  },
  {
    nombre: "Sudadera Dev",
    precio: 32.00,
    stock: 10,
    categoria: "ropa",
    activo: true,
    tallas: ["S","M","L"],           // array
    detalles: {                      // documento embebido
      color: "negro",
      material: "algodon"
    }
  },
  {
    nombre: "Pegatina CSS",
    precio: 1.50,
    stock: 300,
    categoria: "accesorios",
    activo: false,
    etiquetas: ["sticker","frontend","css"]
  }
])

2.3 Insert con fecha y campos opcionales

db.productos.insertOne({
  nombre: "Gorra Node",
  precio: 14.50,
  stock: 25,
  categoria: "accesorios",
  activo: true,
  creadoEn: new Date(),           // fecha actual
  proveedor: { nombre: "DevShop", nif: "B12345678" } // embebido
})
Checkpoint A: ¿Cuántos documentos hay ahora? 
db.productos.countDocuments({})

Paso 3 — READ: busca, proyecta, ordena y pagina

3.1 Listado básico

db.productos.find().limit(5)

Usa limit() para no saturar la consola.

3.2 Proyección (solo campos necesarios)

db.productos.find({}, { nombre:1, precio:1, _id:0 })

3.3 Filtros (operadores)

// Activos
db.productos.find({ activo: true })

// Precio ≤ 20
db.productos.find({ precio: { $lte: 20 } })

// Por texto (regex, sin índice)
db.productos.find({ nombre: /node/i })

3.4 Ordenar y paginar

db.productos.find({}, { nombre:1, precio:1, _id:0 })
  .sort({ precio: 1 })   // asc
  .skip(0)
  .limit(3)

3.5 Búsquedas por campos embebidos y arrays

// Campo embebido
db.productos.find({ "detalles.material": "algodon" })

// Contiene un valor en el array
db.productos.find({ tallas: "M" })

// Contiene todos estos valores
db.productos.find({ etiquetas: { $all: ["sticker","css"] } })

3.6 Conteos

db.productos.countDocuments({ categoria: "accesorios" })
Checkpoint B: ¿Cuántos accesorios activos con precio ≤ 20 tienes? 
db.productos.countDocuments({ categoria:"accesorios", activo:true, precio:{ $lte:20 } })

Paso 4 — UPDATE: modifica documentos con operadores

4.1 Actualiza uno con $set

db.productos.updateOne(
  { nombre: "Taza JavaScript" },
  { $set: { precio: 10.00 } }
)

4.2 Incrementa stock de toda la ropa

db.productos.updateMany(
  { categoria: "ropa" },
  { $inc: { stock: 10 } }
)

4.3 Añade valores a arrays

// Añade una talla si no existe (evita duplicados)
db.productos.updateOne(
  { nombre: "Sudadera Dev" },
  { $addToSet: { tallas: "XL" } }
)

// Inserta al final del array (puede duplicar)
db.productos.updateOne(
  { nombre: "Sudadera Dev" },
  { $push: { tallas: "XS" } }
)

4.4 Upsert (crear si no existe)

db.productos.updateOne(
  { nombre: "Mochila JS" },
  { $set: { precio: 24.99, stock: 40, categoria:"accesorios", activo:true } },
  { upsert: true }
)

4.5 Reemplazar documento (cuidado)

db.productos.replaceOne(
  { nombre: "Pegatina CSS" },
  { nombre: "Pegatina CSS", precio: 1.75, stock: 250, categoria:"accesorios", activo:true }
)

4.6 Ver cambios

db.productos.find({}, { nombre:1, precio:1, stock:1, _id:0 })
Checkpoint C: ¿Existe ahora Mochila JS? ¿Qué tallas tiene Sudadera Dev?

Paso 5 — DELETE: elimina con filtros

5.1 Borrar uno

Elimina el primer documento que cumpla la condición dada.

db.productos.deleteOne({ nombre: "Pegatina CSS" })

5.2 Borrar varios (inactivos)

Elimina todos los documentos que cumplan el filtro indicado.

db.productos.deleteMany({ activo: false })

5.3 Eliminar colección completa con drop()

Si deseas borrar **toda la colección**, puedes usar el método drop(). Este comando elimina la colección completa (estructura y documentos), no solo los datos. 

db.productos.drop()
⚠️ Atención: este comando no se puede deshacer. Después de ejecutarlo, la colección productos dejará de existir en la base de datos.

Para confirmar su eliminación, puedes comprobar:

show collections

Si la colección ha sido borrada correctamente, ya no aparecerá en la lista.

📦 Paso 6 — Crear la colección pedidos y relacionar datos

En este último paso aprenderás a conectar tus colecciones entre sí. Vamos a crear una colección pedidos donde cada documento se vinculará con un cliente (de la colección clientes) y uno o varios productos (de la colección productos).

¿Por qué es importante? Así simulamos relaciones entre datos, igual que en una base relacional, pero usando identificadores únicos (_id) en lugar de claves foráneas.

6.1 Crear la colección clientes (si no existe)

Primero asegúrate de tener algunos clientes de ejemplo:

db.clientes.insertMany([
  { nombre: "Lucía Pérez", email: "lucia@example.com", ciudad: "Madrid" },
  { nombre: "Carlos López", email: "carlos@example.com", ciudad: "Sevilla" }
])

6.2 Crear la colección pedidos con referencias

Vamos a relacionar un cliente con los productos que pidió. Para ello, recuperamos los _id del cliente y de los productos y los usamos como referencias. 

// Buscar un cliente y dos productos
const cliente = db.clientes.findOne({ email: "lucia@example.com" })
const prod1 = db.productos.findOne({ nombre: "Camiseta React" })
const prod2 = db.productos.findOne({ nombre: "Taza JavaScript" })

// Crear el primer pedido
db.pedidos.insertOne({
  clienteId: cliente._id,
  productos: [
    { productoId: prod1._id, cantidad: 2 },
    { productoId: prod2._id, cantidad: 1 }
  ],
  fecha: new Date(),
  estado: "pendiente",
  total: prod1.precio * 2 + prod2.precio
})

6.3 Crea un segundo pedido (otro cliente)

Ahora repite el proceso para otro cliente y producto distinto. 

// Segundo pedido (cliente Carlos López)
const cliente2 = db.clientes.findOne({ email: "carlos@example.com" })
const prod3 = db.productos.findOne({ nombre: "Sudadera Dev" })

db.pedidos.insertOne({
  clienteId: cliente2._id,
  productos: [
    { productoId: prod3._id, cantidad: 1 }
  ],
  fecha: new Date(),
  estado: "enviado",
  total: prod3.precio
})

6.4 Consultar los pedidos creados

Comprueba que se han insertado correctamente. Usa pretty() para ver el formato JSON completo: 

db.pedidos.find().pretty()
Resumen del aprendizaje:
  • Has creado una nueva colección (pedidos) con referencias a clientes y productos.
  • Entiendes cómo funcionan las relaciones en MongoDB mediante el uso de ObjectId.
  • Has practicado la lógica de un pedido real con fecha, estado y total calculado.

5.3 Comprobar

db.productos.countDocuments({})

⚠️ El borrado no se puede deshacer. Revisa siempre el filtro.

🎓 ¿Por qué es importante practicar los comandos en la consola antes de usar Mongoose?

Muchos alumnos se preguntan si vale la pena practicar los comandos del Shell (mongosh) cuando después trabajarán con Mongoose. La respuesta es sí, absolutamente. Esta práctica tiene un valor formativo clave, porque permite comprender cómo piensa realmente MongoDB.

🧩 1️⃣ Comprender qué hace Mongoose “por debajo”

Mongoose no inventa un nuevo lenguaje: traduce tus métodos de alto nivel (create(), find(), updateOne()…) a comandos nativos de MongoDB, los mismos que ejecutas en la consola. Practicar el Shell es como aprender a pensar en MongoDB antes de hablar en Mongoose.

En consola

db.productos.find({ precio: { $lte: 20 } })

En Mongoose

Producto.find({ precio: { $lte: 20 } })

🧠 2️⃣ Desarrollar la mentalidad “orientada a documentos”

En bases relacionales (SQL) se piensa en tablas, claves y relaciones. En MongoDB, se piensa en documentos, colecciones, arrays y operadores. Trabajar con la consola ayuda a visualizar directamente cómo se estructuran y almacenan los datos:

  • Ver la forma real del documento JSON/BSON.
  • Comprender cómo funcionan los operadores ($set, $inc, $push…).
  • Aprender a filtrar, ordenar y proyectar sin depender de frameworks.

💡 3️⃣ Favorecer la autonomía técnica

Un alumno que domina el Shell puede moverse por cualquier entorno MongoDB sin depender del código. Si Mongoose falla, o se trabaja con otra herramienta (Prisma, Typegoose, etc.), entenderá exactamente qué ocurre en la base de datos.

Conclusión: practicar en la consola no es tiempo perdido. Es construir las bases conceptuales para trabajar después con Mongoose, Express o cualquier otro ORM. El alumno pasa de ejecutar comandos → a modelar datos → a crear APIs completas.

📚 4️⃣ Secuencia de aprendizaje recomendada

Etapa Herramienta Objetivo pedagógico
1️⃣ Consola MongoDB (mongosh) Shell local / Atlas Comprender cómo funciona MongoDB de forma nativa. Practicar CRUD, operadores y estructura JSON.
2️⃣ Mongoose ORM para Node.js Aprender a aplicar lo mismo desde el código: esquemas, validaciones, modelos y lógica de negocio.
3️⃣ Express + API REST Servidor Node.js Integrar las operaciones en endpoints y conectar la base con el frontend.

💬 En resumen: el Shell te enseña a “pensar como MongoDB”; Mongoose te enseña a “programar con MongoDB”. Juntas, ambas etapas preparan al alumno para construir aplicaciones reales y comprender todo el flujo de datos.

🛡️ Buenas prácticas al pasar a Mongoose

  • Usa variables de entorno para la URI (nada de contraseñas en código).
  • Define validaciones (required, min, enum) para capturar errores de negocio temprano.
  • Activa timestamps y select/lean cuando toque (rendimiento).
  • Centraliza la conexión (módulo db.js) y maneja errores con try/catch y eventos.
