📈 Evolución Full Stack: De Node a la Persistencia Asíncrona

Este proyecto de API de Biblioteca no es solo una aplicación CRUD funcional, sino una crónica de mi viaje en el desarrollo Full Stack. Aborda los desafíos clave de la arquitectura moderna de aplicaciones y demuestra un dominio práctico del patrón MVC (Modelo-Vista-Controlador) en un entorno real.

🧠 1. La Arquitectura Backend: Node.js, Express y la Persistencia de Datos

El corazón del proyecto reside en el backend, construido con Node.js y el framework Express. Mi principal objetivo fue establecer una API RESTful robusta y modular, manteniendo una estricta separación de responsabilidades:

  • Rutas Modulares (Express Router): Implementé un enrutador dedicado (libros.routes.js) que mapea los verbos HTTP (GET, POST, PUT, DELETE) a funciones específicas del controlador, asegurando que la API sea intuitiva y estándar.
  • Controladores (Lógica de Negocio): La capa de controladores (libros.controller.js) se enfoca exclusivamente en manejar la petición y la respuesta HTTP (validación de entrada, códigos de estado 400/404/201), delegando toda la gestión de datos al Modelo.
  • Persistencia Asíncrona (El Modelo): Este fue un punto de aprendizaje crucial. En lugar de una base de datos tradicional, utilicé un archivo JSON como capa de persistencia (libros.json). El Modelo (libros.model.js) fue diseñado con las siguientes consideraciones avanzadas:
    1. Operaciones No Bloqueantes: Se usó la API de promesas de Node (fs/promises) con async/await para asegurar que las operaciones de lectura/escritura del disco sean no bloqueantes. Esto es fundamental para el rendimiento del servidor.
    2. Robustez y Encapsulación: Se implementó la lógica completa de lectura, modificación, y guardado dentro de funciones atómicas del Modelo (como eliminarLibroPorId), garantizando que el controlador nunca manipule directamente el archivo JSON, promoviendo la integridad de los datos.

Adicionalmente, la configuración de CORS mediante un middleware fue esencial para resolver la política de seguridad del navegador, permitiendo la comunicación fluida entre orígenes distintos (el frontend y el backend).

🎨 2. Frontend Reactivo: Vanilla JS y la Conexión Asíncrona

En la capa de presentación, el objetivo fue construir una interfaz de usuario funcional utilizando Vanilla JavaScript y el motor de renderizado del navegador, demostrando que puedo manejar la manipulación del DOM y la lógica de la aplicación sin depender de librerías externas complejas.

  • Consumo de API (fetch): Se utilizó fetch con la sintaxis async/await para consumir los endpoints de la API, manejando asíncronamente tanto la carga inicial de datos como el envío de formularios y la eliminación de elementos.
  • Gestión Dinámica del DOM: La lista de libros se renderiza dinámicamente (`GRID.innerHTML = libros.map(...)`), y se implementó la delegación de eventos en el contenedor principal para manejar acciones de elementos generados dinámicamente (como el botón "Eliminar"). Esta técnica es crucial para la eficiencia y el rendimiento del frontend.
  • Experiencia de Usuario (UX) y Accesibilidad (A11y): Se añadió manejo de errores y mensajes de estado claros (`setMsg`). Además, la estructura HTML se enriqueció con atributos ARIA (`role="status"`, `aria-live="polite"`) para asegurar que los cambios de contenido sean notificados a usuarios de tecnologías de asistencia.

Este proyecto sirve como una prueba tangible de mi capacidad para diseñar, implementar y depurar soluciones Full Stack coherentes, desde la gestión de I/O en el servidor hasta la interacción con el usuario en el navegador. Demuestra resiliencia en el manejo de dependencias, protocolos y patrones de arquitectura.
