Tipos de datos en MongoDB

Aprende a guardar texto, números, fechas, listas y objetos paso a paso.

🏠 Inicio ⬅ Tema anterior Siguiente tema ➜

📘 1️⃣ ¿Qué son los tipos de datos?

Los tipos de datos indican qué clase de información puede tener cada campo dentro de un documento. MongoDB guarda los datos en formato JSON (texto con llaves y comas) y cada valor puede ser texto, número, sí/no, fecha, lista, etc.

Cuando hagas tu CRUD, deberás elegir el tipo correcto para cada campo: nombre → texto, edad → número, activo → verdadero/falso, etc.

🧱 2️⃣ Tipos básicos que usaremos en clase

📝 Texto (String)

Para guardar palabras, nombres, correos, direcciones, etc.

{
  "nombre": "María González",
  "email": "maria@email.com",
  "ciudad": "Sevilla"
}

🔢 Números (Number)

Para edades, precios, cantidades, notas… No llevan comillas.

{
  "edad": 25,
  "precio": 19.99,
  "stock": 30
}

✅ Verdadero o falso (Boolean)

Para campos que solo pueden tener dos valores: true (sí) o false (no).

{
  "activo": true,
  "admin": false
}

📅 Fechas (Date o String)

MongoDB puede guardar fechas, pero es más fácil usar texto.

  • Versión sencilla : "2025-11-05"
  • Versión completa (avanzada): new Date("2025-11-05")
{
  "fechaRegistro": "2025-11-05"
}

🚫 Vacío (null)

Sirve cuando un dato no existe o está pendiente.

{
  "telefono": null,
  "linkedin": null
}

📚 3️⃣ Tipos que dan estructura

📦 Listas (Array)

Permiten guardar varios valores dentro de un mismo campo.

{
  "idiomas": ["Español", "Inglés", "Francés"],
  "notas": [8.5, 9, 7.5]
}

🏠 Objetos anidados (Object)

Sirven para agrupar información relacionada dentro de un mismo documento.

{
  "direccion": {
    "calle": "Gran Vía 12",
    "ciudad": "Madrid",
    "codigoPostal": "28001"
  }
}

🆔 Identificador (_id)

MongoDB crea automáticamente un _id único para cada documento, no hace falta escribirlo tú.

{
  "_id": "507f1f77bcf86cd799439011",
  "nombre": "Pedro"
}

🧩 4️⃣ Documento completo de ejemplo

Veamos un ejemplo real con todos los tipos básicos combinados. Este tipo de documento ya se puede usar en un CRUD.

{
  "nombre": "Ana García",
  "edad": 28,
  "email": "ana.garcia@email.com",
  "activo": true,
  "fechaRegistro": "2025-01-15",
  "direccion": {
    "calle": "Calle Mayor 45",
    "ciudad": "Barcelona",
    "codigoPostal": "08001"
  },
  "habilidades": ["JavaScript", "MongoDB", "HTML"],
  "telefono": null
}

👉 Observa que cada valor tiene un tipo diferente, pero todo se guarda dentro de un solo documento.

🧠 5️⃣ Consejos para tus primeros proyectos

  • Usa comillas solo para texto.
  • No pongas comillas en números o booleanos.
  • Usa "AAAA-MM-DD" para fechas sencillas.
  • No abuses de anidar objetos o listas dentro de listas.
  • Mantén los mismos tipos en todos los documentos (si “edad” es número, que lo sea siempre).

💬 7️⃣ Conclusión

MongoDB te permite guardar datos de forma natural, casi igual que escribir un objeto de JavaScript. Con solo entender estos tipos (texto, número, booleano, fecha, lista y objeto) ya puedes crear y leer tus propios documentos.

En el siguiente tema veremos cómo se organizan en colecciones y cómo hacer un CRUD completo con ellos.

🚀 6️⃣ ¡A Practicar! Crea tu primera BBDD en Mongoo. Vamos al lio.

Ya sabes qué es una bbdd, qué es una bbdd no sql y ahora ya conoces los los tipos de datos que usa MongoDB. ¡Es hora de ponerlos en acción!

Primeros pasos (¡Es gratis y fácil!):

  1. Regístrate en la plataforma de MongoDB (Mongoo/Atlas). Es como abrir una cuenta de correo, pero para bases de datos.
  2. Crea tu primer Cluster: Esto es como pedir tu propio servidor en la nube. Tómate el tiempo de elegir un nombre divertido.
  3. Dentro del Cluster, crea una nueva base de datos llamada mongoo y una colección llamada alumnos.
  4. ¡Hora de insertar documentos! Crea al menos tres documentos diferentes en la colección alumnos usando los tipos de datos que has aprendido: 
    {
  "nombre": "Pedro",
  "edad": 22,
  "email": "pedro@email.com",
  "activo": true,
  "fechaRegistro": "2025-01-15",
  "direccion": {
    "calle": "Calle Falsa 123",
    "ciudad": "Madrid",
    "codigoPostal": "28001"
  },
  "habilidades": ["JavaScript", "MongoDB"],
  "telefono": null
}
  5. Explora tus documentos: Usa las herramientas de MongoDB Atlas para ver y modificar los documentos que has creado.
  6. ¿Qué es un cluster? Un cluster es un conjunto de servidores que trabajan juntos para almacenar y gestionar tus bases de datos en la nube. Es como tener tu propio equipo de servidores dedicado a tus datos.
  7. ¿Qué es una colección? Una colección es un grupo de documentos en MongoDB, similar a una tabla en una base de datos relacional.
  8. ¿Qué es un documento? Un documento es una unidad de datos en MongoDB, que se almacena en formato JSON y puede contener diferentes tipos de datos.
  9. ¿Qué es un campo? Un campo es una clave dentro de un documento que almacena un valor. Es similar a una columna en una tabla relacional.
    • Ejemplo de campo: en el documento de un usuario, "nombre" es un campo que almacena el nombre del usuario.

    Recuerda que los campos pueden contener diferentes tipos de datos, como texto, números, booleanos, fechas, listas y objetos.

    Ejemplo de campo: en el documento de un usuario, "nombre" es un campo que almacena el nombre del usuario.

    Dirección es un campo que almacena un objeto con información sobre la ubicación del usuario.

    Habilidades es un campo que almacena una lista de habilidades del usuario.Un Array

    Activo es un campo que almacena un valor booleano indicando si el usuario está activo o no.

    Teléfono es un campo que almacena un valor nulo, indicando que no se ha proporcionado un número de teléfono pero ya está preparado para recibirlo.

    Fecha de Registro es un campo que almacena la fecha en que el usuario se registró en la plataforma.

    ¿es posible no declarar un campo y luego en el formulario incluirlo y que se cree directamente en el documento? Sí, MongoDB permite la creación dinámica de campos. Si un campo no está declarado en el esquema, se puede agregar en cualquier momento simplemente incluyendo el campo en el documento.
    Ejemplo: Si en el formulario de registro se incluye un campo "telefono" que no estaba en el esquema original, MongoDB lo añadirá automáticamente al documento. ¿aunque no estuviera declarado como null? Sí, incluso si el campo no estaba declarado inicialmente, MongoDB lo añadirá al documento con el valor proporcionado en el formulario, ya sea un valor específico o null si no se proporciona ningún valor.
    En resumen, MongoDB es flexible y permite la evolución de los documentos a lo largo del tiempo.
