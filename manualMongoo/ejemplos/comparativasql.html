SQL vs MongoDB — Comparación Visual

Estructura, consultas, y usos recomendados para tu Manual Mongoo.

En SQL (relacional) trabajas con tablas (filas+columnas) y esquemas rígidos; en MongoDB (NoSQL) trabajas con colecciones y documentos JSON con esquema flexible. Esta guía te ayuda a elegir con criterio y a ver código en paralelo.

Modelo Relacional (SQL)

Tabla: alumnos

-- Esquema
CREATE TABLE alumnos (
  id SERIAL PRIMARY KEY,
  nombre VARCHAR(100) NOT NULL,
  edad INT,
  ciudad VARCHAR(100)
);

-- Inserción
INSERT INTO alumnos (nombre, edad, ciudad)
VALUES ('Ana López', 20, 'Sevilla');

-- Consulta
SELECT id, nombre, ciudad
FROM alumnos
WHERE edad >= 20
ORDER BY nombre ASC;

Documento (MongoDB)

Colección: alumnos

// Inserción
db.alumnos.insertMany([
  { nombre: "Ana López", edad: 20, ciudad: "Sevilla" },
  { nombre: "Luis Díaz", correo: "luis@example.com", activo: true }
]);

// Consulta
db.alumnos.find(
  { edad: { $gte: 20 } },
  { nombre: 1, ciudad: 1 }
);

// Actualización
db.alumnos.updateOne(
  { nombre: "Ana López" },
  { $set: { ciudad: "Córdoba" } }
);

Comparativa esencial

Aspecto SQL (Relacional) MongoDB (NoSQL)
Estructura Tablas → filas & columnas; esquema fijo Colecciones → documentos JSON; esquema flexible
Relaciones Claves primarias/foráneas; JOINs Referencias o datos embebidos; agregaciones
Integridad Fuerte (constraints, transacciones ACID) Buena (transacciones multi-documento), enfoque flexible
Escalado Vertical (y horizontal con complejidad) Horizontal por particionado (sharding) nativo
Consultas SQL declarativo, joins potentes API de consultas con operadores y pipelines
Esquemas Rígidos; migraciones formales Flexibles; evolución por versiones de documento

Usos recomendados

¿Cuándo elegir SQL?

  • Datos altamente estructurados y consistencia estricta.
  • Procesos financieros, contabilidad, inventarios con integridad referencial.
  • Informes complejos y joins entre muchas tablas.
  • Analítica BI tradicional (OLTP/OLAP con modelos en estrella/copo).
  • Regulaciones que exigen transacciones ACID fuertes.

¿Cuándo elegir MongoDB (Mongoo)?

  • Contenido JSON con estructura variable y anidada.
  • Apps web/mobile en Node.js con cambios de modelo frecuentes.
  • Escalado horizontal y alto volumen de lecturas/escrituras.
  • Catálogos, perfiles, comentarios, feeds, IoT, logs.
  • Prototipado ágil donde el esquema evoluciona con el producto.

💡 Regla práctica: si tu dominio es muy relacional y crítico (banca, ERP), empieza por SQL. Si tu dominio es documento‑centrado, cambia mucho y necesita escalar horizontalmente, empieza por MongoDB.

De “filas/columnas” a “documentos/claves”

SQL → Fila
