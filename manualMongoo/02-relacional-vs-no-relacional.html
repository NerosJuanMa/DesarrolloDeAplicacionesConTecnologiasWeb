Relacional vs. No relacional

Diferencias fundamentales entre SQL y NoSQL

🏠 Inicio ⬅ Tema anterior Siguiente tema ➜

🏗️ Base de datos RELACIONAL (SQL)

Organiza datos en tablas con filas y columnas; relaciones mediante claves. Para una introducción general, revisa Tema 1 · Filas/Columnas.

📋 Características

  • Estructura rígida (esquema predefinido)
  • Relaciones con claves foráneas
  • Consultas con SQL
  • Transaccionalidad ACID

Ejemplo minimal en SQL

CREATE TABLE usuarios (
  id INT PRIMARY KEY AUTO_INCREMENT,
  nombre VARCHAR(100) NOT NULL,
  email VARCHAR(100) UNIQUE
);
CREATE TABLE posts (
  id INT PRIMARY KEY AUTO_INCREMENT,
  titulo VARCHAR(200),
  contenido TEXT,
  usuario_id INT,
  FOREIGN KEY (usuario_id) REFERENCES usuarios(id)
);

🗂️ Base de datos NO RELACIONAL (NoSQL)

Almacena datos de forma flexible, a menudo como documentos JSON en colecciones. Para primera toma de contacto, repasa Tema 1 · Tipos.

📋 Características

  • Esquema flexible (documentos pueden variar)
  • Datos anidados o referencias
  • Escalabilidad horizontal
  • Consistencia eventual (ver BASE)

Ejemplo minimal en MongoDB

// Documento en "usuarios"
{
  "_id": "507f1f77bcf86cd799439011",
  "nombre": "Ana García",
  "email": "ana@email.com",
  "posts": [{ "titulo": "Mi primer post", "fecha": "2025-01-15" }],
  "perfil": { "edad": 25, "ciudad": "Madrid" }
}

🧭 ¿Cuándo usar cada una?

Usa RELACIONAL (SQL) si…

  • Relaciones complejas y reporting potente
  • Consistencia fuerte
  • Transacciones críticas
  • Esquema estable

Ejemplos: banca, ERP, inventarios.

Usa NO RELACIONAL (NoSQL) si…

  • Esquema flexible o cambiante
  • Escalado horizontal y disponibilidad
  • Grandes volúmenes y tiempo real
  • Iteración rápida (MVPs)

Ejemplos: redes sociales, catálogos, IoT, analytics.
