Manual Técnico: Comunicación Frontend ↔ Backend

Guía técnica completa del flujo de datos entre script.js y server.js en la aplicación CRUD de canciones

🏗️ Arquitectura y Conceptos Técnicos Fundamentales

📚 Conceptos Clave que Debes Dominar:

  • Cliente-Servidor: Separación de responsabilidades entre frontend (cliente) y backend (servidor)
  • API REST: Conjunto de endpoints HTTP que permiten operaciones CRUD
  • JSON: Formato de intercambio de datos entre frontend y backend
  • HTTP Methods: GET (leer), POST (crear), PUT (actualizar), DELETE (eliminar)
  • Asynchronous Programming: Uso de async/await para operaciones no bloqueantes
FRONT = navegador (HTML/CSS/JS) BACK = Express (Node.js) JSON = formato de datos HTTP = protocolo de comunicación
Flujo Técnico Completo: 1) INICIALIZACIÓN → DOMContentLoaded ejecuta obtenerTodasLasCanciones() 2) GET /api/canciones → Express router ejecuta app.get() 3) LECTURA → leerCanciones() usa fs.readFileSync() + JSON.parse() 4) RESPUESTA → res.json() serializa datos y envía HTTP response 5) FRONTEND → fetch() recibe response, await response.json() deserializa 6) RENDERIZADO → mostrarCancionesEnPantalla() manipula DOM 7) POST/PUT/DELETE → Operaciones de escritura activan guardarCanciones() 8) PERSISTENCIA → fs.writeFileSync() + JSON.stringify() actualiza archivo

🗺️ Mapeo Técnico Completo Frontend ↔ Backend

Función Frontend HTTP Method Endpoint Backend Función Backend Operación de Archivo
obtenerTodasLasCanciones() GET /api/canciones app.get() → leerCanciones() READ: fs.readFileSync() + JSON.parse()
crearNuevaCancion(datos) POST /api/canciones app.post() → guardarCanciones() WRITE: JSON.stringify() + fs.writeFileSync()
actualizarCancionExistente(id, datos) PUT /api/canciones/:id app.put() → findIndex() → guardarCanciones() UPDATE: Modifica array + fs.writeFileSync()
eliminarCancion(id) DELETE /api/canciones/:id app.delete() → splice() → guardarCanciones() DELETE: splice() + fs.writeFileSync()

Middleware Stack en server.js:

🔧 Funciones Técnicas Clave:

  • express.json(): Middleware que parsea req.body en POST/PUT
  • JSON.parse(): Convierte string del archivo a objeto JavaScript
  • JSON.stringify(): Convierte objeto JavaScript a string para archivo
  • fs.readFileSync(): Lectura síncrona del archivo JSON
  • fs.writeFileSync(): Escritura síncrona al archivo JSON

🔍 Análisis Técnico Detallado por Operación CRUD

📖 READ - Obtener Todas las Canciones (GET /api/canciones)

🌐 Frontend (script.js)

async function obtenerTodasLasCanciones() {
    try {
        mostrarIndicadorCarga(true);
        
        // fetch() hace HTTP GET request
        const respuesta = await fetch(URL_API);
        
        // response.json() deserializa el JSON del servidor
        const datos = await respuesta.json();
        
        if (datos.exito) {
            // Manipulación del DOM
            mostrarCancionesEnPantalla(datos.datos);
            actualizarContador(datos.datos.length);
            mostrarMensaje(datos.mensaje, 'exito');
        }
    } catch (error) {
        // Error handling para fallos de red
        mostrarMensaje('No se puede conectar con el servidor', 'error');
    } finally {
        mostrarIndicadorCarga(false);
    }
}

🖥️ Backend (server.js)

app.get('/api/canciones', (peticion, respuesta) => {
    // Llamada a función auxiliar
    const canciones = leerCanciones();
    
    // Respuesta HTTP con JSON serializado
    respuesta.json({
        exito: true,
        datos: canciones,
        mensaje: `Se encontraron ${canciones.length} canciones`
    });
});

function leerCanciones() {
    try {
        // Lectura síncrona del sistema de archivos
        const contenido = fs.readFileSync(ARCHIVO_CANCIONES, 'utf8');
        
        // Parsing de JSON string a JavaScript array
        const canciones = JSON.parse(contenido);
        return canciones;
    } catch (error) {
        // Manejo de errores de archivo
        return [];
    }
}

⚠️ Diferencia Técnica Crítica:

express.json() solo parsea el cuerpo de peticiones HTTP (POST/PUT). Para leer archivos del sistema, necesitas JSON.parse() explícitamente.

➕ CREATE - Crear Nueva Canción (POST /api/canciones)

🌐 Frontend (script.js)

async function crearNuevaCancion(datosCancion) {
    try {
        const respuesta = await fetch(URL_API, {
            method: 'POST',                    // HTTP Method
            headers: {
                'Content-Type': 'application/json'  // MIME type
            },
            // Serialización de objeto a JSON string
            body: JSON.stringify(datosCancion)
        });
        
        const datos = await respuesta.json();
        
        if (datos.exito) {
            mostrarMensaje(datos.mensaje, 'exito');
            limpiarFormulario();
            // Re-fetch para actualizar la UI
            obtenerTodasLasCanciones();
        }
    } catch (error) {
        mostrarMensaje('Error al guardar la canción', 'error');
    }
}

🖥️ Backend (server.js)

app.post('/api/canciones', (peticion, respuesta) => {
    // express.json() ya parseó req.body
    const { titulo, artista, año } = peticion.body;
    
    // Validación de datos
    if (!titulo || !artista || !año) {
        return respuesta.status(400).json({
            exito: false,
            mensaje: 'Faltan datos requeridos'
        });
    }
    
    const canciones = leerCanciones();
    
    // Creación del nuevo objeto
    const nuevaCancion = {
        id: obtenerSiguienteId(canciones),
        titulo: titulo.trim(),
        artista: artista.trim(),
        año: parseInt(año)
    };
    
    // Mutación del array
    canciones.push(nuevaCancion);
    
    // Persistencia al archivo
    if (guardarCanciones(canciones)) {
        respuesta.status(201).json({
            exito: true,
            datos: nuevaCancion,
            mensaje: `Canción "${nuevaCancion.titulo}" creada`
        });
    }
});

🔧 Detalles Técnicos:

  • HTTP Status 201: Indica "Created" según estándar HTTP
  • Content-Type header: Especifica formato JSON para el parser
  • ID Generation: Algoritmo para evitar colisiones de IDs
  • Data Sanitization: trim() elimina whitespace, parseInt() convierte tipos
✏️ UPDATE - Actualizar Canción (PUT /api/canciones/:id)

🌐 Frontend (script.js)

async function actualizarCancionExistente(id, datosCancion) {
    try {
        // Template literal para URL con parámetro
        const respuesta = await fetch(`${URL_API}/${id}`, {
            method: 'PUT',
            headers: {
                'Content-Type': 'application/json'
            },
            body: JSON.stringify(datosCancion)
        });
        
        const datos = await respuesta.json();
        
        if (datos.exito) {
            mostrarMensaje(datos.mensaje, 'exito');
            limpiarFormulario();
            obtenerTodasLasCanciones();
        }
    } catch (error) {
        mostrarMensaje('Error al actualizar', 'error');
    }
}

🖥️ Backend (server.js)

app.put('/api/canciones/:id', (peticion, respuesta) => {
    // Extracción del parámetro de ruta
    const id = parseInt(peticion.params.id);
    const { titulo, artista, año } = peticion.body;
    
    const canciones = leerCanciones();
    
    // Búsqueda por índice usando findIndex()
    const indice = canciones.findIndex(c => c.id === id);
    
    if (indice === -1) {
        return respuesta.status(404).json({
            exito: false,
            mensaje: `No se encontró canción con ID ${id}`
        });
    }
    
    // Reemplazo completo del objeto en el array
    canciones[indice] = {
        id: id,  // Preservar ID original
        titulo: titulo.trim(),
        artista: artista.trim(),
        año: parseInt(año)
    };
    
    if (guardarCanciones(canciones)) {
        respuesta.json({
            exito: true,
            datos: canciones[indice],
            mensaje: 'Canción actualizada exitosamente'
        });
    }
});

🔧 Algoritmos Utilizados:

  • findIndex(): Búsqueda lineal O(n) para localizar elemento
  • Route Parameters: Express parsing de :id en la URL
  • Immutable ID: Preservación del identificador único
  • HTTP 404: Status code para recurso no encontrado
🗑️ DELETE - Eliminar Canción (DELETE /api/canciones/:id)

async function eliminarCancion(id) {

            method: 'DELETE'  // Solo método, no body needed
        });

            mostrarMensaje(datos.mensaje, 'exito');
            obtenerTodasLasCanciones();
        }
    } catch (error) {
        mostrarMensaje('Error al eliminar', 'error');
    }
}

    // Event binding dinámico
    botonConfirmarEliminar.onclick = () => {

        modalConfirmar.classList.add('oculto');
    };

🖥️ Backend (server.js)

app.delete('/api/canciones/:id', (peticion, respuesta) => {
    const id = parseInt(peticion.params.id);
    const canciones = leerCanciones();
    
    const indice = canciones.findIndex(c => c.id === id);
    
    if (indice === -1) {
        return respuesta.status(404).json({
            exito: false,
            mensaje: `No se encontró canción con ID ${id}`
        });
    }
    
    // splice() modifica array in-place y retorna elemento eliminado
    const [cancionEliminada] = canciones.splice(indice, 1);
    
    if (guardarCanciones(canciones)) {
        respuesta.json({
            exito: true,
            datos: cancionEliminada,  // Retornar elemento eliminado
            mensaje: `Canción "${cancionEliminada.titulo}" eliminada`
        });
    }
});

🔧 Técnicas de Eliminación:

  • splice(index, 1): Eliminación in-place que retorna array con elemento eliminado
  • Destructuring: [cancionEliminada] extrae primer elemento del array retornado
  • UI Confirmation: Modal pattern para prevenir eliminaciones accidentales
  • Soft Delete Alternative: Podrías usar flag "activo: false" en lugar de splice()

🧩 JSON, express.json(), parse() y stringify(): Los Pilares del Intercambio de Datos

🎯 Conceptos Fundamentales que Debes Dominar:

Estos tres elementos son la columna vertebral de cualquier aplicación web moderna, incluyendo cuando trabajas con bases de datos.

🔧 express.json(): El Intérprete de Peticiones HTTP

¿Qué hace exactamente express.json()?

Es un middleware que actúa como un "traductor automático" para las peticiones HTTP que llegan al servidor.

🚫 Sin express.json()

app.post('/api/canciones', (req, res) => {
    console.log(req.body); // undefined ❌
    
    // Tendríamos que parsear manualmente:
    let rawData = '';
    req.on('data', chunk => {
        rawData += chunk;
    });
    req.on('end', () => {
        try {
            const datos = JSON.parse(rawData); // Manual parsing
            // Ahora sí podemos usar los datos
        } catch (error) {
            // Manejar errores de parsing
        }
    });
});

✅ Con express.json()

// Configuración una sola vez
app.use(express.json());

app.post('/api/canciones', (req, res) => {
    // ¡req.body ya es un objeto JavaScript! ✨
    console.log(req.body); // { titulo: "...", artista: "..." }
    
    const { titulo, artista, año } = req.body; // Funciona perfectamente
    
    // Podemos usar los datos inmediatamente
});

🔍 Detalles Técnicos:

  • Cuándo actúa: Solo en peticiones POST, PUT, PATCH (que envían datos en el body)
  • Content-Type requerido: "application/json" en el header
  • Límite de tamaño: Por defecto 100kb (configurable)
  • Qué NO hace: No lee archivos del sistema, solo peticiones HTTP
📝 JSON.parse(): El Deserializador

🎯 Función: Convertir texto JSON → Objeto JavaScript

Toma un string con formato JSON y lo convierte en un objeto/array que JavaScript puede manipular.

📁 Leyendo Archivos

// server.js
function leerCanciones() {
    try {
        // fs.readFileSync() devuelve STRING
        const contenidoTexto = fs.readFileSync('canciones.json', 'utf8');
        console.log(typeof contenidoTexto); // "string"
        console.log(contenidoTexto); 
        // '[{"id":1,"titulo":"Bohemian Rhapsody",...}]'
        
        // JSON.parse() convierte string → array/object
        const cancionesArray = JSON.parse(contenidoTexto);
        console.log(typeof cancionesArray); // "object"
        console.log(Array.isArray(cancionesArray)); // true
        
        return cancionesArray; // Ahora podemos usar .push(), .filter(), etc.
    } catch (error) {
        console.error('Error parsing JSON:', error);
        return []; // Array vacío si falla
    }
}

🌐 Respuestas de APIs

// script.js
async function obtenerTodasLasCanciones() {
    const respuesta = await fetch(URL_API);
    
    // respuesta.text() devolvería STRING
    const textoJSON = await respuesta.text();
    console.log(typeof textoJSON); // "string"
    
    // Pero response.json() hace JSON.parse() automáticamente
    const datosObjeto = JSON.parse(textoJSON);
    // Equivale a: await respuesta.json()
    
    console.log(typeof datosObjeto); // "object"
    return datosObjeto;
}

⚠️ Errores Comunes con JSON.parse():

// ❌ JSON inválido
JSON.parse('{nombre: "Juan"}'); // Error: falta comillas en "nombre"

// ❌ String vacío
JSON.parse(''); // Error: Unexpected end of JSON input

// ❌ undefined o null
JSON.parse(undefined); // Error: Unexpected token u

// ✅ Siempre usar try-catch
try {
    const datos = JSON.parse(contenidoArchivo);
    return datos;
} catch (error) {
    console.error('JSON inválido:', error.message);
    return null; // O valor por defecto
}
💾 JSON.stringify(): El Serializador

🎯 Función: Convertir Objeto JavaScript → String JSON

Toma un objeto/array de JavaScript y lo convierte en texto JSON para guardarlo o enviarlo.

💾 Guardando en Archivos

// server.js
function guardarCanciones(cancionesArray) {
    try {
        // cancionesArray es un Array de JavaScript
        console.log(typeof cancionesArray); // "object"
        console.log(Array.isArray(cancionesArray)); // true
        
        // JSON.stringify() convierte array → string
        const textoJSON = JSON.stringify(cancionesArray, null, 2);
        console.log(typeof textoJSON); // "string"
        console.log(textoJSON);
        /*
        [
          {
            "id": 1,
            "titulo": "Bohemian Rhapsody",
            "artista": "Queen",
            "año": 1975
          }
        ]
        */
        
        // fs.writeFileSync() requiere STRING
        fs.writeFileSync('canciones.json', textoJSON);
        return true;
    } catch (error) {
        console.error('Error stringifying JSON:', error);
        return false;
    }
}

📡 Enviando por HTTP

// script.js
async function crearNuevaCancion(datosCancion) {
    // datosCancion es un objeto JavaScript
    console.log(typeof datosCancion); // "object"
    console.log(datosCancion);
    // { titulo: "Mi canción", artista: "Artista", año: 2024 }
    
    const respuesta = await fetch(URL_API, {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json' // ¡Importante!
        },
        // JSON.stringify() convierte objeto → string
        body: JSON.stringify(datosCancion)
        // HTTP solo puede enviar texto, no objetos
    });
}

🔧 Parámetros de JSON.stringify():

JSON.stringify(value, replacer, space)

// value: el objeto a convertir
// replacer: función/array para filtrar propiedades (opcional)
// space: número de espacios para indentación (opcional)

// Ejemplos:
JSON.stringify(obj);           // Compacto (sin espacios)
JSON.stringify(obj, null, 2);  // Con indentación de 2 espacios
JSON.stringify(obj, ['id', 'titulo']); // Solo propiedades específicas
🗄️ JSON y Bases de Datos: El Futuro de tu Aplicación

🚀 ¿Cómo Cambia con Bases de Datos?

Cuando migres de archivos JSON a bases de datos (MongoDB, PostgreSQL, MySQL), estos conceptos siguen siendo fundamentales.

📊 Con MongoDB (Base de Datos NoSQL):

// MongoDB maneja objetos JavaScript nativamente
const { MongoClient } = require('mongodb');

app.post('/api/canciones', async (req, res) => {
    // express.json() sigue parseando req.body ✅
    const { titulo, artista, año } = req.body;
    
    const nuevaCancion = { titulo, artista, año };
    
    // MongoDB almacena directamente el objeto (internamente usa BSON)
    const resultado = await db.collection('canciones').insertOne(nuevaCancion);
    
    res.json({ exito: true, datos: resultado });
    // ❌ NO necesitas JSON.stringify() para MongoDB
});

app.get('/api/canciones', async (req, res) => {
    // MongoDB devuelve objetos JavaScript directamente
    const canciones = await db.collection('canciones').find().toArray();
    
    res.json({ exito: true, datos: canciones });
    // ❌ NO necesitas JSON.parse() para MongoDB
});

🐘 Con PostgreSQL/MySQL (Bases de Datos SQL):

// Con bases SQL, a veces necesitas JSON.stringify/parse para campos JSON
const { Pool } = require('pg'); // PostgreSQL

app.post('/api/canciones', async (req, res) => {
    // express.json() sigue parseando req.body ✅
    const { titulo, artista, año, metadatos } = req.body;
    
    // Si 'metadatos' es un objeto complejo, stringify para SQL
    const metadatosJSON = JSON.stringify(metadatos);
    
    const query = 'INSERT INTO canciones (titulo, artista, año, metadatos) VALUES ($1, $2, $3, $4)';
    await pool.query(query, [titulo, artista, año, metadatosJSON]);
});

app.get('/api/canciones', async (req, res) => {
    const result = await pool.query('SELECT * FROM canciones');
    
    // Parsear campos JSON de la base de datos
    const canciones = result.rows.map(row => ({
        ...row,
        metadatos: JSON.parse(row.metadatos) // Parse campos JSON
    }));
    
    res.json({ exito: true, datos: canciones });
});

🎯 Ejercicio Práctico: Flujo Completo de Datos

🔄 Sigue el Dato: De Frontend a Archivo y Vuelta

Veamos paso a paso cómo viaja un dato desde el formulario hasta el archivo JSON:

FLUJO COMPLETO - CREAR CANCIÓN: 1) 👤 USUARIO escribe en formulario: titulo: "Imagine", artista: "John Lennon", año: 1971 → Tipo: HTML form elements (strings) 2) 🌐 FRONTEND captura con JavaScript: const datosCancion = { titulo, artista, año: parseInt(año) } → Tipo: Objeto JavaScript 3) 📡 HTTP REQUEST - fetch() + JSON.stringify(): body: '{"titulo":"Imagine","artista":"John Lennon","año":1971}' → Tipo: String JSON (lo que viaja por la red) 4) 🖥️ EXPRESS.JSON() parsea automáticamente: req.body = { titulo: "Imagine", artista: "John Lennon", año: 1971 } → Tipo: Objeto JavaScript (otra vez) 5) 📁 BACKEND lee archivo con fs.readFileSync(): contenido = '[{"id":1,...}]' ← String del archivo → Tipo: String JSON 6) 🔄 JSON.PARSE() convierte a array: canciones = [{ id: 1, ... }] → Tipo: Array JavaScript 7) ➕ MANIPULACIÓN - agregar nueva canción: canciones.push({ id: 2, titulo: "Imagine", ... }) → Tipo: Array JavaScript (modificado) 8) 💾 JSON.STRINGIFY() prepara para archivo: textoJSON = '[{"id":1,...},{"id":2,"titulo":"Imagine",...}]' → Tipo: String JSON 9) 📁 FS.WRITEFILESYNC() guarda en disco: canciones.json ← String JSON escrito al archivo → Tipo: Archivo de texto 10) 📡 RESPUESTA HTTP - res.json(): '{"exito":true,"datos":{...},"mensaje":"..."}' → Tipo: String JSON (respuesta HTTP) 11) 🌐 FRONTEND recibe con response.json(): datos = { exito: true, datos: {...}, mensaje: "..." } → Tipo: Objeto JavaScript 12) 🎨 DOM UPDATE - mostrar en pantalla: HTML actualizado con la nueva canción → Tipo: Elementos HTML visibles

💡 Puntos Clave del Flujo:

  • 3 conversiones críticas: Object→String→Object→String→Object
  • express.json() actúa solo en paso 4 (peticiones HTTP entrantes)
  • JSON.parse() en paso 6 (archivos) y paso 11 (response.json())
  • JSON.stringify() en paso 3 (envío) y paso 8 (archivo)
  • HTTP siempre transporta texto, nunca objetos JavaScript

🤔 FAQ Técnico para Desarrolladores

¿Por qué express.json() no funciona para leer archivos?

express.json() es middleware que solo parsea el cuerpo de peticiones HTTP entrantes. Cuando lees un archivo con fs.readFileSync(), obtienes un string que necesitas convertir manualmente con JSON.parse().

// ❌ Incorrecto
const datos = fs.readFileSync('datos.json'); // string

// ✅ Correcto  
const datos = JSON.parse(fs.readFileSync('datos.json', 'utf8'));
¿Cuándo usar await vs .then()?

async/await es sintaxis más limpia para el mismo concepto que .then():

// Estilo .then() - más verboso
fetch(URL_API)
    .then(response => response.json())
    .then(datos => mostrarCanciones(datos))
    .catch(error => manejarError(error));

// Estilo async/await - más legible
try {
    const response = await fetch(URL_API);
    const datos = await response.json();
    mostrarCanciones(datos);
} catch (error) {
    manejarError(error);
}
¿Por qué re-fetch después de crear/editar/eliminar?

Garantiza consistencia de datos entre frontend y backend. Alternativas:

  • Optimistic Updates: Actualizar UI inmediatamente, asumir éxito
  • Response Data: Usar datos del response para actualizar UI
  • State Management: Mantener estado local sincronizado
// Optimistic update (más complejo pero mejor UX)
function eliminarCancionOptimistic(id) {
    // 1. Actualizar UI inmediatamente
    removerCancionDelDOM(id);
    
    // 2. Hacer request
    fetch(`/api/canciones/${id}`, { method: 'DELETE' })
        .catch(() => {
            // 3. Revertir si falla
            obtenerTodasLasCanciones();
            mostrarError('No se pudo eliminar');
        });
}

🎯 Puntos Clave para Dominar la Arquitectura

🔥 Conceptos Críticos que Debes Entender:

  • Separación de Responsabilidades: Frontend maneja UI/UX, Backend maneja datos/lógica
  • Stateless HTTP: Cada request es independiente, no hay memoria entre requests
  • JSON como Lingua Franca: Formato universal de intercambio de datos
  • Event-Driven Architecture: UI responde a eventos del usuario, triggea API calls
  • Error Handling: Siempre manejar casos de fallo en red, validación, etc.
  • Async Programming: Operaciones de red nunca bloquean la UI

// Middleware de protección
function requireAuth(req, res, next) {
    const token = req.headers.authorization;
    if (!token) return res.status(401).json({ error: 'Token requerido' });
    
    try {
        const decoded = jwt.verify(token, SECRET_KEY);
        req.user = decoded;
        next();
    } catch (error) {
        res.status(401).json({ error: 'Token inválido' });
    }
}

// Proteger rutas existentes
